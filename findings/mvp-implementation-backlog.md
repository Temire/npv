## Implementation order notes

1. The active change is a small part of item 1. The broader submission journey still needs submitter contact and agent-affidavit decisions, an authenticated end-to-end run, and evidence of database persistence.
2. Item 2 is deliberately an explicit prerequisite before exposing search reports or certificate data publicly. The client must decide the field-level publication policy; implementation should then be treated as feature-enabling authorization, rather than a broad standalone security audit.
3. Keep verification lookup, paid report output and analytics as separate user journeys. The client discussion distinguishes them and leaves payment entitlements unsettled.
4. Re-run the relevant neighboring journey after every shared component change: submit/resubmit, survey map/overlap, approval/certificate, owner vault, public search and admin review.
